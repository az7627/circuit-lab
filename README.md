# 电路实验室

面向中学生的中文直流电路虚拟实验室。原生 HTML、CSS、JavaScript 和 SVG；网页版无需安装依赖。Windows、macOS、Linux 和 Android 均使用系统 WebView，网页资源均随应用打包，可离线使用。

在仓库目录运行 `npm run dev`，打开 http://127.0.0.1:4173/ 。`npm test` 检查电路求解、导线、保存及反馈，`npm run test:drag` 验证鼠标及无需长按的触屏拖动、落点、取消、撤销和点击添加，`npm run check` 检查全部 JavaScript 模块语法。安装 Chrome 后可运行 `npm run test:ui`，检查自动保存、单行顶栏、悬浮属性、栏位收起、深浅色偏好、鼠标缩放与真实双指事件；也可设置 `CIRCUIT_LAB_BROWSER=msedge` 使用 Edge。截图保存在 `artifacts/ui/`。

## 桌面版与 Android 版

以下命令在本 Git 仓库（`circuit-lab/`）执行。打包需要 Node.js 22.21.1 或以上，首次运行 `npm ci` 安装锁定版本的依赖。两端直接打包 `dist/` 的现有网页，无需运行本地服务器。`dist/` 是版本管理中的网页源码，请勿删除或加入忽略规则。

### 桌面版

桌面版使用 Tauri，不随应用打包浏览器内核。Windows 使用已安装的 Microsoft Edge WebView2 Runtime，macOS 使用系统 WKWebView，Linux 使用 WebKitGTK 4.1。Windows 安装程序不下载或安装 WebView2，缺少运行时的机器须先安装 [Microsoft WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)。Linux DEB 声明系统 WebKitGTK/GTK 依赖，免安装压缩包同样使用系统运行时，面向 Ubuntu 24.04 或兼容环境。系统运行时及开发依赖见 [Tauri 官方说明](https://v2.tauri.app/start/prerequisites/)。

安装 Rust 1.97.1 和对应系统开发工具后执行：

```powershell
npm run system:dev            # 开发启动
npm run system:build          # 当前平台的系统 WebView 安装包
npm run test:system           # 验证实际原生程序的保存、主题、导出和全屏
```

软件和窗口统一称为“电路实验室”。Windows 使用中文安装向导，默认安装到当前用户的 `CircuitLab` 目录，也可自选目录。后续升级沿用原安装位置和固定应用标识，不清空实验。旧中文目录版本需先自行卸载。

输出目录 `release/system-webview/`，Windows 提供安装程序和免安装 EXE，macOS 提供 DMG/ZIP，Linux 提供 TAR.GZ/DEB。Linux 不使用会携带 WebKitGTK 的 Tauri AppImage。发布版均使用系统 WebView，与旧版 Electron 版本使用独立数据目录，切换时可用 JSON 导出、导入实验。

### Android

Android 版使用 Capacitor 和系统 WebView，支持 Android 7.0（API 24）及以上，需使用更新的 Android System WebView。构建需要 Android Studio、JDK 21、SDK Platform 36、37 及 SDK Build Tools 36.0.0，并在 SDK Manager 接受相关许可证。环境说明见 [Capacitor](https://capacitorjs.com/docs/getting-started/environment-setup)。

```powershell
npm ci
npm run android:build          # 同步网页，构建可直接安装的 debug APK
npm run android:open           # 同步资源并在 Android Studio 中打开原生工程
npm run android:sync           # 仅同步网页和恢复 Gradle wrapper
npm run test:android           # 已启动模拟器或连接设备时，验证原生保存重载和文件导出
$env:ANDROID_SERIAL='emulator-5554' # 多设备时指定实际测试设备
```

默认输出 `release/android/CircuitLab-<版本>-android-debug.apk`。首次构建会下载 Gradle、缺失的已授权 SDK 和 Maven 依赖，之后应用本身可完全离线运行。构建脚本自动查找常见位置的 SDK 和 JDK；也可设置 `ANDROID_HOME`、`JAVA_HOME`，或用 `CIRCUIT_LAB_JAVA_HOME` 单独指定打包用的 JDK。使用 JDK 21。

Android 原生代码位于 `android/`，实验保存于应用私有数据。系统返回键依次关闭对话框、取消接线、退出全屏或收起侧栏，最后将应用移至后台。导出实验及备份通过 Android 的「另存为」选择位置，无需存储权限；文件导入沿用系统文件选择器。应用隐藏时立即保存草稿。

正式 APK/AAB 使用自己的签名密钥。将以下环境变量设置为已有密钥库的信息（密钥库路径须为绝对路径），再运行 `npm run android:release` 或 `npm run android:bundle`：

| 环境变量 | 含义 |
| --- | --- |
| `ANDROID_KEYSTORE_FILE` | 密钥库绝对路径 |
| `ANDROID_KEYSTORE_PASSWORD` | 密钥库密码 |
| `ANDROID_KEY_ALIAS` | 密钥别名 |
| `ANDROID_KEY_PASSWORD` | 私钥密码 |

分别输出 `release/android/CircuitLab-<版本>-android-release.apk` 和 `CircuitLab-<版本>-android-release.aab`。未提供签名配置时会报错，不退回调试签名。`npm run android:ci` 执行 Release Lint、APK/AAB 构建及签名校验。版本名称取自 `package.json`，Android `versionCode` 使用 `主版本 × 10000 + 次版本 × 100 + 修订版本`（次版本、修订版本均须小于 100）；预发布标记不影响 versionCode。

发布证书固定为已核实的 v2.9.0 证书，指纹写在 `android/release-certificate.json`；构建前核对密钥库，Actions 还核对保存的公钥，任何不匹配都会停止。v2.8.2 与 v2.9.0 的官方 release APK 证书相同，v2.8.2 附件也已重新签署核实；旧 debug APK 使用不同签名。旧调试包首次切换请先导出实验备份，再卸载旧调试版并安装正式版。自 v2.9.1 起调试版使用 `.debug` 独立包名，可与正式版共存。

### Git 与构建产物

只管理源码、文本配置、`package-lock.json` 和 `src-tauri/Cargo.lock`。`.openai/`、`release/`、`artifacts/`、`node_modules/`、Rust/Android 构建缓存、机器路径、签名密钥以及 EXE/APK/AAB/JAR/压缩包均已忽略。原生图标使用可提交的 SVG/XML；Gradle wrapper JAR 不提交，构建脚本会从 Gradle 官方仓库恢复并校验固定 SHA-256，Gradle 分发包也校验 SHA-256。克隆后先运行 `npm ci` 和 `npm run android:sync`，再从 Android Studio 构建。

## GitHub Actions 自动检查与发版

日常流程：修改源码 → 提交 PR 或推送 `main` → CI 检查 → 推送版本标签 → 自动构建并公开 [GitHub Release](https://github.com/az7627/circuit-lab/releases)。npm 发布暂缓，根包保持 `private: true`。

`CI` 工作流在 Windows x64、macOS ARM64/Intel、Ubuntu x64 上运行语法、单元测试及桌面启动检查。`Build and Release` 工作流构建 Tauri 系统 WebView 桌面版和 Android 系统 WebView APK/AAB，并运行检查、Lint 和签名校验。Linux 使用 Xvfb/Openbox 虚拟显示环境。Android CI 不启动模拟器。

所有构建检查通过后，只读的附件校验任务会收齐 10 个安装包，检查文件名、完整性及非空内容；手动构建也执行此步骤。随后发布任务生成 `SHA256SUMS.txt`，先上传草稿再公开 Release。`-alpha.N`、`-beta.N`、`-rc.N` 版本会标记为 GitHub 预发布版且不会设为 Latest；稳定版本设为 Latest。安装包仅作为 Actions 产物及 Release 附件保存，不进入 Git。构建任务只有读取权限，只有最终发布任务获得 `contents: write`；使用 GitHub 自动提供的令牌，无需手动配置 GitHub 发布 Token。官方 Actions 固定到提交 SHA。

### 后续发布一个新版本

工作区保持干净，在 `main` 上执行：

```powershell
npm version patch
git push origin main --follow-tags
```

`npm version` 自动同步包与锁文件版本、创建版本提交和标签。正式版本使用 `patch` / `minor` / `major`；预发布使用完整版本号，例如 `npm version 2.10.0-beta.1`，然后推送带 `v` 前缀的标签。标签必须与两处版本一致，次版本和修订版本须小于 100，以保持 Android 版本号递增。

在 GitHub Actions 选择 `Build and Release` → `Run workflow` 可手动构建当前分支。手动运行只提供可下载产物，不创建或公开 Release。未通过时查看对应任务日志和 diagnostics 附件；修复源码后重新构建。网络或上传问题可重跑同一标签并补齐草稿；已经公开的版本和附件不会被覆盖，代码修复需要新版本号。诊断与临时产物保留 7 天，Release 附件长期保留。

### Android 发布密钥的恢复与校验

Windows 上已登录 GitHub CLI 后，可运行 `pwsh -File scripts/setup-android-signing.ps1`。脚本仅使用已有 v2.9.0 密钥，缺少密钥或证书不匹配时拒绝更新 Secrets，不生成替代私钥。默认备份位置为用户目录 `.android/circuit-lab-signing/`，位于仓库外且仅当前用户可访问。`credentials.dpapi.xml` 的密码由 Windows DPAPI 加密，仅原 Windows 用户可解密；迁移机器前应在原用户环境将密钥和密码备份至自己的安全存储。

脚本将以下内容写入仓库的 GitHub Actions Secrets，日志只显示名称及公开证书指纹：

| Secret | 用途 |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | 固定发布密钥库内容 |
| `ANDROID_KEYSTORE_PASSWORD` | 密钥库密码 |
| `ANDROID_KEY_ALIAS` | 密钥别名 |
| `ANDROID_KEY_PASSWORD` | 私钥密码 |
| `ANDROID_RELEASE_PUBLIC_KEY` | 从 v2.9.0 证书核实的 SPKI PEM 公钥 |
| `ANDROID_RELEASE_CERT_SHA256` | 从 v2.9.0 证书核实的 SHA-256 指纹 |

CI 在 runner 临时目录恢复密钥，签名后删除临时文件。密钥或恢复文件丢失时不要重新生成替换已有正式签名，应从备份恢复。`npm run check:git` 在 CI 中阻止二进制、生成目录或密钥进入 Git 文件列表。

## 搭建与观察

- 画布顶部可在「电路图」和「实物图」之间切换。15 种元件均有实物外观，两种模式共用电路连接关系、参数与实时读数，分别保存元件位置、朝向和视角。首次从实物图转为电路图时，先合并导线连接的电气节点，再识别串联链、并联支路与电压表测量支路，重新排布符号。支持桥式结构与一般图的分层布局；连接关系变化时重新生成电路图，重复切换则恢复各自布局。电路图转实物图时先识别电气节点，消去串在导线上的辅助节点，以接线柱直连；先明确并联的分流节点、汇流节点和各支路的串联元件，混联递归分组；实物按器材外形、端子朝向及支路关系独立摆放，电源位于器材下方，不要求与电路图保持相同的相对位置。电流表在用电器分类中视作导线、电压表视作开路，但保留它们所在干路、支路及测量范围；电压表探针直接跨接被测部分，不让主回路借道电压表接线柱。分流与汇流可落在电源、电表或用电器的实际接线柱上，串联返回支路按接线顺序与电源排成下方一行，并联部分通过相邻接线柱汇接。自动生成以无交叉为约束，分别尝试汇接位置、接线柱短链及器材排布；先完成全部导线，再留出自然弧度，避开器件和名称。若不能形成无交叉布局，保留原电路并提示，不展示交叉的自动转换结果。自动布局与手动调整分别记录，旧的交叉自动布局在互转时重排。切换按钮会立即反馈，旧版布局在下次转换时升级。
- 实物图使用自由导线：在导线工具下，点击接线端或节点，移动鼠标后再点击终点；也可按住接线端或节点拖到终点。导线沿鼠标轨迹绘制，落在空白处自动创建终点节点。导线工具下操作元件主体仍然是选择、移动，双击开关仍可切换状态。按 `Esc` 取消未完成的导线。
- 实物导线路径与电路图走线分别保留。拖动时用曲率传递、余量收紧和局部避障连续调整导线，接线端附近保持自然出线方向，避免逐帧整条重算。只调整与所移动元件或节点关联的电路；未接线元件和其他独立电路不会触发已有线路重排。在拖动预览中按“先减少交叉，再避开元件，最后兼顾原轨迹与长度”的顺序局部修复，松手直接保存最后一帧，不再重新布线。实物避障使用灯泡玻璃、底座等实际外形区域。手绘路径在切换模式和修改参数时保留。两种模式均可在导线上插入分支节点，交叉导线不会自动接通。当前模式、布局缓存及自由路径随草稿、实验、JSON 文件及备份保存，旧版自动转换布局会在下次互转时更新。
- 实物电表为三接线柱结构：左侧公共负端，中间为小量程正端，右侧为大量程正端。电流表量程为 0.6 / 3 A，电压表为 3 / 15 V，通过改接正接线柱切换；指针、刻度与实际读数使用同一量程，显示超量程和反接提示。电路图保留两个接线端，接入的小量程接线柱会映射到正端，两种模式的连接不变。
- 15 种元件：电源、小灯泡、电阻、开关、双掷开关、电流表、电压表、滑动变阻器、电动机、电铃、电热丝、电容、发光二极管、线圈、保险丝。
- 画布没有空间边界，拖动空白处平移，滚轮和缩放按钮提供平滑缩放；触屏可用双指缩放、平移，画布始终跟随手指。元件、节点、导线拐点及当前视角一起自动保存。新放置电源默认横向，负极在左、正极在右。电流表、电压表默认同样左负右正。选择元件不会改变视角。鼠标、触屏与键盘选择统一使用虚线框，仅覆盖图形本体及少量边距，名称和参数文字不参与点击判定，方便在旁边放置节点与接线。
- 三种工具排成一行：选择用于选择和移动，导线用于放节点和接线，删除用于删除点击的目标。撤销与重做在下一行。工具与元件库共用一个滚动区域；如果放在左侧会让画布宽度小于高度，会自动移至上方。添加元件后保留当前工具。
- 接线节点模式点击空白处放置节点，点击节点或元件接线端开始连线，再点击目标接线端结束。连线期间点击空白处创建终点节点并结束本次接线；再次点击起点即可连接下一段。点击导线插入分支节点。点击元件主体可以选择和移动，双击开关快速切换通断。双掷开关有公共端 C 和支路 1、2，双击切换接通的支路，也可在右侧属性选择；两个支路不会同时接通。
- 导线位于元件上方，可以选中及单独删除覆盖元件的导线。普通导线交叉不会自动接通，实心节点上的所有支路接通。电路图的 T 形及多支路连接自动绘制实心点，包括直接在元件接线端分出的支路；普通转角不打点。初次自动整理时采用平直母线；编辑已成形电路时保留原有线路、手动节点和测量支路，只为新增连线规划直角路径，避开元件及文字。直接短接用电器、跨接多个串联元件和在同一节点上补接电压表均可绘制，不会把原线路压缩到一条新母线上。尚未成形的自动母线可以随新支路延长，完成的旁路与测量接线不再被后续分支重排。结束接线时可吸附到附近的导线或接线柱。
- 顶栏统一提供实验名称、视图切换、缩放、加载、导出、全屏、帮助和设置。工作区填满窗口剩余空间，左上角按钮可以展开或收起实验侧边栏，三个栏位按钮始终在左上角排成一行，可独立展开或收起侧边栏、工具栏和顶栏，按钮颜色不随展开状态变化。顶栏保持单行，空间不足时依次隐藏品牌文字、隐藏操作按钮文字、将视图名称缩为「电路 / 实物」、隐藏标志，再隐藏实验名称和重命名按钮、将视图切换改为图标；仍放不下时，保留放大、缩小、比例和适应画布，将右侧的清空、加载、导出、全屏、帮助与设置收进三点菜单，选项统一左对齐。总读数卡片已移除，属性只在选中元件、节点或导线时以圆角卡片悬浮显示，背景仅覆盖实际内容，画布尺寸和视角保持不变。Android 全屏通过原生接口同时隐藏状态栏和导航栏，退出全屏或按系统返回键恢复；网页版请求隐藏浏览器导航界面的全屏，具体支持由浏览器决定。
- 根据实际连接拓扑计算总电流、端电压、等效电阻和元件功率，检测开路与短路。支持多节电池，串联电压相加、反接相减，同电压电池并联分担电流；冲突的理想电源接法会提示检查。简单的两端电源组显示实际电压和干路电流，多组或多端电源分别测量。
- 灯泡明暗和电热丝红热程度随功率变化。电动机圈内 M 上叠加风扇，转速与方向跟随反电动势，启动、减速和反转保留当前转角；属性中可按住转子观察堵转电流。电铃通过 Web Audio 发声，供电同时改变响度、敲击频率和锤头振幅；断电停止，页面隐藏时静音。小灯泡底座不放置易与接线柱混淆的装饰螺钉。
- 外观默认跟随系统深浅色，也可在设置中固定为浅色或深色，选择在重启后保留。画布、工具栏、属性卡片、菜单和对话框均适配深色模式。电流方向显示可在设置中切换。模拟持续运行，无需暂停按钮。
- 操作帮助中可载入串联、并联和欧姆定律示例。实验数据记录面板已移除，旧文件中的记录仍保留以兼容导入与备份。

## 保存与管理实验

没有创建或打开实验时，只显示创建与导入入口。点击「创建新实验」命名后加入列表，或导入已有实验；全部修改自动保存，无需手动保存。侧栏可以新增、重命名、归档及删除实验；删除有二次确认，归档直接移至右上角设置中的「已归档实验」，可恢复。移走最后一个可用实验后回到创建与导入界面。

顶栏提供「导出实验」和「加载实验」。单个实验使用 JSON 文件，包含完整电路、元件参数、开关状态、视角与布局缓存。加载文件时创建新的实验，同名内容自动标注「导入」，保留已有实验及草稿。双掷开关的 C、1、2 标记在各个旋转方向都保持正向。

实验保存在当前浏览器的本地存储中，不自动跨设备同步。在设置中导出 JSON 备份可保存全部实验、归档内容与旧版草稿；导入时合并实验，不覆盖已有列表。旧版草稿可以在设置中恢复为新实验，之后自动保存。删除元件后会使引用其端子的旧视图接线缓存失效，保留当前电路和其余元件的位置。数据校验失败、存储配额不足与存储权限被阻止分别提示，保存失败不覆盖上一次成功保存的内容。浏览器为站点分配的存储配额与硬盘剩余空间不同，详见 [Web Storage 规范](https://html.spec.whatwg.org/multipage/webstorage.html#dom-storage-setitem)。

旧 `circuit-lab-v1` 电路、蜂鸣器、变阻器及实验记录兼容升级；旧存储保留。新集合使用 `circuit-lab-experiments-v2`。每个实验最多 200 个元件、500 个节点、1000 根导线和 500 条测量记录，坐标没有画布边界。

快捷键：`V` 选择，`J` 接线节点，`E` 删除，`Ctrl+Z` 撤销，`Ctrl+Shift+Z` 或 `Ctrl+Y` 重做，`Ctrl+S` 保存，`F` 全屏，`Esc` 退出全屏或取消接线，`0` 适应画布。选择元件或节点后用方向键移动。

## 模型说明

实物图重画的思路参考 [OpenStax Physics 19.3 中的不规则电路重画例题](https://openstax.org/books/physics/pages/19-3-parallel-circuits)：先追踪连接节点及各条路径，再确定串并联关系，弯曲导线的外形不决定电路拓扑。两种表示可以采用不同的辅助节点和导线编号，但保留每个元件的端子身份和电气连接。各自的完整接线、位置和视角独立缓存，随实验文件保存；往返转换恢复原有手绘布局。

电源电动势与内阻分别可调，默认内阻 0 Ω 保持原实验兼容；有内阻时按 U端 = E − Ir 求路端电压，并计算内阻发热。导线和电流表理想零电阻，电压表无限电阻。灯泡、电铃线圈、电热丝仍采用固定电阻近似。电表量程用于刻度、指针及超量程显示；不模拟表内电阻。

滑动变阻器有左下固定端 A、右下固定端 B 和上方滑片 P。最大阻值与滑片位置分别调节：A–P 和 B–P 的阻值相反变化，A–B 恒为全电阻，支持三端分压。旧文件默认滑片位于最右端，保留原有 A–P 有效电阻。电动机采用圈内 M 的符号，以 U = E反 + Ir 求电流，另有简化的转动惯量、摩擦和阻尼模型，区分线圈发热 I²r 与机械功率 E反I；电动机整体不按 U = Ir 处理。电铃采用向上半圆和两条引线的示意图形，参考科学出版社《学会电工识图的10堂课》1.12 节：[出版社原文](https://www.ecsponline.com/yz/BFC0B9B8DF9984E41B9ED007856D65E2F000.pdf)。

电容使用后向欧拉伴随模型计算充电、储能和无电源放电，包含 0.05 Ω 等效串联电阻；电荷随实验保存，可清空电荷重看过程，并以 10 倍或 100 倍慢放观察。慢放作用于当前实验的动态仿真时间。独立调用 solveCircuit 而不传暂态状态时，仍返回电容断路的稳态解。LED 采用正向压降加 10 Ω 动态电阻的分段模型，反向截止；亮度随正向电流变化，超过 20 mA 时提示增加串联限流电阻。理想线圈仍在稳态直流时短路。保险丝冷态电阻 0.2 Ω，超过可调额定电流时熔断，可在属性栏更换。

声音、转速、亮度和红热程度用于定性教学，不输出校准后的声压、转速或温度。运行 `npm run test:circuits` 可验证真实端子点击、截图电路互转、串并联结构、充放电与元件属性界面，截图位于 `artifacts/circuits/`。`npm run test:editing` 用真实点击验证电压表接线、直接短接、手动节点跨接，以及撤销、重载后的几何保留，截图位于 `artifacts/editing/`。

部署文件位于 `dist/`，本机 Sites 配置可放在已忽略的 `.openai/hosting.json`。
